# ADR-002: 采用 rquickjs 作为 JS 扩展运行时

## 状态

已接受 (Accepted)

## 上下文

HertaBase 作为一个高度可扩展的 BaaS，允许用户通过编写 JavaScript / TypeScript Hook 脚本来定制业务逻辑。为了执行这些 Hook，系统需要在后端的 Rust 微内核中集成一个 JS 运行时。该运行时必须符合以下要求：

1. **轻量与可嵌入**：不能带来庞大的体积膨胀。
2. **严格的沙箱安全**：用户提交的脚本在执行时不能危及宿主服务器的安全。
3. **可度量的初始化成本**：每个根调用重建独立上下文，需要在本项目工作负载上测量初始化延迟与内存占用。

## 考虑的替代方案

- **V8 / deno_core**：提供 JIT 和较完整的运行时设施，需要额外评估构建、分发和隔离成本；本项目未做性能对比测量。
- **Boa**：纯 Rust 实现，可避免 C 引擎绑定，但仍需验证本项目要求的异步执行、中断与配额行为。
- **Wasmer / Wasmtime**：基于 WebAssembly 范式，安全性和跨语言特性极为优秀。但由于要求用户将逻辑编译为 Wasm 模块再运行，会大幅增加终端用户的学习门槛和开发复杂度。

## 决策

HertaBase 决定采用 **rquickjs**（基于 QuickJS 的 Rust 绑定）作为内置的 JS 扩展运行时。

运行时定位为应用级扩展环境，而不是只执行按文件名匹配的 Hook。启动脚本通过显式 API 注册
Event Hooks、自定义路由和定时任务；宿主通过 `$app` 提供 Record/Collection 数据访问、邮件、
受限 HTTP、实时事件、沙盒文件与结构化日志。详细公开契约和安全边界见
[JavaScript 扩展运行时设计](../js-runtime.md)。

HTTP 使用专用、禁代理和禁自动重试的客户端，每跳 DNS 解析后固定全部经过校验的地址，并以原主机名校验 TLS。
cron 的名字互斥、重试和日历匹配属于宿主状态，独立于热重载快照；任务每次尝试仍重建 JS 上下文。
应用消息与数据库 LIVE 通知分离，沿用连接配额，但在入队和出队重新核对当前账户及 audience。
扩展文件使用逻辑目录、不可变物理版本与持久化配额预留；未知存储结果不会释放预留。
可靠投递使用与业务写入共同提交的宿主 outbox。发送前落盘 sending 状态，SMTP 及无接收端幂等保证的 HTTP
结果不确定时停在 unknown，必须运维核对；不会把超时解释成未送达。
这些能力的 Windows 测试记录见 [实施验证](../js-runtime-validation.md)，不据此推断其他平台验证通过。

## 后果 (Consequences)

### 优势 (Pros)

- **可嵌入接口**：提供独立 Runtime/Context、内存与栈限制，以及中断回调。
- **异步宿主桥接**：可以在专用线程执行 JS，将宿主 I/O 交给 Tokio。
- **二进制内存归属**：请求与文件字节通过独立的有界缓冲跨线程，宿主缓冲预留随原生调用存活。回到 JS 时复制到 QuickJS 分配的 Uint8Array，避免外部 ArrayBuffer 绕过 JS 堆限制；文件 HTTP 响应持有缓冲所有者直至响应释放。JSON 元数据与字节分别传输，旧 JSON 宿主接口保留转换入口。宿主内部完整临时分配计量及正文读取前接纳仍见[验证记录](../js-runtime-validation.md)中的剩余项。
- **明确的测量边界**：目前没有本项目冷启动、吞吐或分发体积的性能承诺。

### 劣势 (Cons)

- **缺少 JIT 编译**：计算密集型脚本需要按本项目的实际工作负载测量，当前没有与 V8 的性能比较结论。
- **生态较小**：相较于 Node.js / Deno 庞大的标准库和模块生态，开发者在编写脚本时可直接利用的第三方原生依赖较为受限。
- **宿主 API 维护成本**：数据库、网络、邮件、实时和文件能力都必须由 Rust 显式桥接、授权和版本化，不能直接复用 Node.js 标准库。
- **版本补丁维护**：固定 `rquickjs = 0.11.0`。Windows 实测发现默认异步驱动连续清空微任务队列，且 bundled QuickJS 的 Promise Before/After 钩子未覆盖普通 reaction/await。运行时采用逐任务预算检查，并通过私有 continuation token 补齐上下文恢复。补丁出处与哈希见 [vendor/README.md](../../vendor/README.md)。升级前必须重跑循环中断、分支隔离、OOM 和销毁测试。
